# ugg v0.5.8 — 持ち越しを片付ける

**リリース日**: 2026-09-29
**タグ**: `v0.5.8`
**テーマ**: v0.5.7 までに見つけて裁定に含めていなかったもののうち、ユーザーの情報が外へ出る・ログに残る 2 件と、
更新の確かめが事実と違う側に倒れうる 1 件を直す。**新機能ゼロ。** 依存とモデルの版は変えていない（v0.5.7 のまま）。

## なぜこの回だったか

当初のテーマは「ローカル AI と並んで喋る」だった（LM Studio が同じ GPU で文章を作っている間、高品質モードの 1 文に
数秒〜十数秒かかる）。着手前の spike で測ると、生成中は 1 文 11〜14 秒（取り合いが無ければ 0.4〜0.5 秒）で、
**CPU と GPU の優先度を上げても変わらず、8 ステップにしても 3 割減るだけ**だった。LLM 側も 70 → 9 tok/s に落ちる。
ugg の中で必ず重なるのは独り言の補充 1 か所だけで、ほかのアプリの生成は ugg から制御できない。ユーザー裁定でテーマを
変え、取り合いは取説の FAQ のままにした（spec §4.5.1 の既知の事項）。

## 入れたもの（3 項目 + 記録）

| | 内容 |
|---|---|
| 1 | **ログとエラー文に URL を丸ごと載せない** — reqwest のエラー文からは URL を一律に外す（失敗しうる呼び出しすべて）。ユーザーが設定した URL・入力から作った URL は、スキームとホストまでしか書かない（カレンダーの合言葉・時事ネタの検索語・天気の座標・LLM の接続先・更新通知のフィード・地名検索）。時事ネタの失敗のログから検索語そのものも外した |
| 2 | **声を作るたびに Hugging Face へ問い合わせない** — 上流は合成のランタイムを作るたびに透かしの重みの版を Hub に聞いていた（誰も操作していないのに外へ出る通信。通信が詰まる環境では最初の声が約 20 秒遅れた）。合成・参照音声の生成・更新の確認のプロセスは、透かしの重みが手元に揃っていれば `HF_HUB_OFFLINE=1` で走る。揃っていなければ今までどおり上流が取り直す（先取りに失敗した環境の回復経路を残す）。通信なしで足りないときは「更新する」で直る理由に言い分ける |
| 3 | **更新の確認の子プロセスは、結果を書いたら後片付けを通さずに抜ける** — CUDA を使ったあとの終了処理で落ちると、合成できていても更新を戻す側に倒れた（実例は無い防御） |
| 4 | **記録** — v0.5.7 の反証レビューが残した「確かめていない懸念」6 件を実測で閉じた（Hub への要求は透かしの 1 本だけ・v4.1 本体とトークナイザは問い合わせない・警告の行は hub 1.33 で出ない・xet は共有の logs に 1 本書くだけ・パスは最長 245 文字）。GPU の取り合いの実測を spec の既知の事項へ |

spec §3.3（外へ出るもの）に、更新通知と音声の資産の取得を書き足した。

## 反証レビュー（別 Opus）が崩した前提

「足りないものは、ugg が入れた環境では起きない」は透かしの重みについて偽だった。先取りは失敗しても導入・更新を止めない
設計で、失敗の文言は「合成のときにもう一度取りに行きます」。一律に通信を止めると、先取りに失敗した環境では透かしが
二度と効かない。→ 重みが揃っているときだけ止める形にした（契約は変えない）。

## リリース前監査（release-audit）が出したもの — タグ前に修正（`d2b3ecc`）

1. **URL を外しているかを見張る走査が、ソース全体を見ていなかった** — 各ファイルの最初の `#[cfg(test)]` より前だけを
   読んでおり、関数の途中に `#[cfg(test)]` がある `irodori_download.rs` と、頭にテスト用の impl がある `sidecar.rs` の
   後ろのほうが見えていなかった。spec と test-plan の「src 全体」は実際より強い記述だった。テストの塊だけを除く形に
   改め、`match … .await {` で受ける 4 か所にも URL を外す処理を通した
2. 通信なしで足りないときの判定が、処理の最中に別の理由で出た例外（`__context__`）までたどっていた → 包んだ原因だけに
3. 共有キャッシュの場所の決め方で `%VAR%` を展開していなかった

## 既知の制限

- ローカル LLM が同じ GPU で文章を作っている間は、高品質モードの 1 文に数秒〜十数秒かかる（取説 FAQ・spec §4.5.1）
- v3 を読む経路（v0.5.7 の更新を済ませていない環境・更新が全戻ししたあとの確かめ直し）も通信なしで読む。共有 HF
  キャッシュが掃除されていると、確かめ直しが事実と違う説明になりうる（この端末には v3 が無く確かめていない）
- 過去の `ugg.log` に残った URL は消さない（取説 11 章: ファイルごと消してよい）
