## 概要

v0.3.0 (2026-07-24) に続くリリース。機能追加が 2 バージョン続いたため、**「基盤・完成度」**
に充てた回（spec §6.0、設計正本 docs/foundation-design.md）。目玉は 2 つで、どちらも
**新機能というより「spec が以前から要求していたのに実装が追いついていなかった分の解消」**にあたる。

1. **表示モニタの選択**（M13、spec §4.1.6）— マルチモニタ環境で、キャラを出す画面を選べる
2. **advanced 独り言の LLM 生成 + 時事ネタの織り込み**（M14、spec §4.4.4 / §4.4.6）—
   advanced モードの独り言が AI 生成になり、興味分野のニュースが感想として混ざる

あわせて **API キーが一度も永続化されていなかった致命的な不具合**を修正した（下記）。

## 変更点

### 表示モニタの選択 (M13、spec §4.1.6)

- 設定「基本」→「表示モニタ」で、接続中のモニタから表示先を選べる。選んだ瞬間に移動する
- **ユーザーの明示選択が常に優先**。1 秒ごとの位置監視が選択を上書きしない構造にした
  （モニタ決定を `resolve_target_monitor` の 1 関数に集約）
- 選択は `app_settings.monitor_pref` に永続化され、再起動しても保たれる
- 選択したモニタが見つからないときは主モニタへ退避するが、**選択は消さない**。
  つなぎ直せば自動で戻る。ただし解像度やモニタの並びが変わった場合は「別構成」と判断して
  主モニタに置く（誤ったモニタに固定されるより安全側、spec §4.1.6 の直訳）
- DPI（拡大率）の異なるモニタへの移動に対応するため、`apply_dock` を
  `set_position` → `set_size` の順に変更した（移動してから寸法を決める）

### advanced 独り言の LLM 生成とキャッシュ (M14、spec §4.4.4)

- advanced モードの独り言を LLM が生成し、**複数件まとめて DB に貯めてから少しずつ話す**。
  発話のたびに API を呼ばないので、呼び出し回数は独り言の回数より大幅に少ない
- ストックは **DB (`monologue_cache`) なので再起動をまたいで保持**される（起動のたびに
  補充が走らない）
- **AI 非依存は維持**（spec §4.2.1）。low モード / 降格中 / API キー無し / 通信失敗 /
  タイムアウト / 応答破損 / 月額上限超過 / 在庫切れ / 失効 / ゴースト未読込 / DB エラーの
  **すべてで辞書の独り言に落ちる**。この経路が丸ごと死んでも独り言は止まらない
- **コスト管理は advanced 会話と同じ扱い**。補充の前後で月額上限を評価し、超過したら
  チャット経路と同じ降格・告知に合流する。会計も同じ `api_usage` に記録する
- 独り言を無効（間隔 0）にしている場合は補充も走らない

### 時事ネタの織り込みと賞味期限 (M14、spec §4.4.6)

- 興味分野のニュース見出しを**独り言の生成時に材料として渡す**（追加の API 呼び出しは無し）。
  ニュースの要約ではなく、**見聞きしたことへの感想をひとこと漏らす**形にプロンプトで制約している
- **賞味期限 1 週間を二段で担保**する:
  - 織り込み時 — 取得から 7 日を超えた見出しは材料に使わない
  - **発話時** — ストックは補充から時間が空いて話されうるので、話す時点で見出しが 7 日を
    超えていたらその文を使わず辞書の独り言に差し替える
- 時事ネタを含まない独り言も、生成から 30 日を超えたら使わない
- 興味分野から外したキーワードの見出しは材料に使わない
- **時事ネタをオフに戻すと、織り込み済みのストックをその場で破棄**する
  （オフにしたのに 1 週間ニュースの話を続けない）
- 履歴クリアの対象に含まれる（`include_profile` に関係なく常に消える）

### 不具合修正

- **API キーが永続化されない致命的不具合を修正**。`keyring` 3.x はプラットフォームの
  ストア feature を明示しないと OS の資格情報ストアを組み込まず、メモリ上のモックに
  フォールバックする。そのため保存時は「保存しました」と出るのに、設定を開き直すと
  「未保存」に戻り、LLM 呼び出しには鍵が乗らず 401 になっていた。
  **この状態では advanced モードが一度も機能していなかった。** `windows-native` を
  有効化して修正し、回帰テストを追加した（実ストアへの往復を検査する）
- 補充の LLM タイムアウトを 20 → 120 秒に延長。独り言 5 件の生成は一文の言い換えより
  出力量が桁違いで、**ローカル LLM（LMStudio / Ollama）では必ずタイムアウトしていた**

### 品質・負債返済 (M15)

- test-plan §5 に日常支援（spec §4.6）の手動チェック G-1〜G-19 を新設
- architecture.md のモジュール一覧と実体の乖離 8 件を解消
- reader 系 2 spec のヘッダを実態に更新
- Irodori 上流 3 資産の版指定を commit 固定に統一

## 契約の変更（後方互換）

- **DB スキーマ v8 → v9**。`monologue_cache` テーブルを新設（既存テーブルは無変更）。
  起動時に自動で適用され、既存データは保持される
- **新規 Tauri コマンド 2 件**: `list_monitors` / `set_monitor_pref`（M13）。M14 は新規コマンドなし
- **新規イベント: なし**
- **新規 Settings フィールド: なし**（モニタ選択は `app_settings.monitor_pref` に保存）

## 既知の制限 (このリリースでは対応しない)

- **モニタごとに別々のキャラ X 位置は記憶しない**（移動時は新しいステージ幅へ clamp する
  だけ。spec §6.6 の残件）
- **キャラのドラッグでモニタを跨ぐことはできない**（動かすのはステージごと = モニタ選択で行う）
- 選択中のモニタを外して**残り 1 台**になった場合だけ、「選択中のモニタが見つかりません」の
  注記より「モニタが 1 台のため選択できません」が優先表示され、select も「自動」に見える。
  選択自体は保持されている（test-plan A-14 に併記）
- 発話の emit に失敗したときだけ、取り出し済みのストックが 1 件失われる（頻度が低いため受容）
- バック起点の発話は chat_log に一律 `mode="low"` で記録される（既存挙動。M14 の生成文も
  同じラベルになる）
- 音声入力は不採用（spec §6.2。音声でのやり取りは完成度を極める必要があり時期尚早と判断）

## 動作要件

v0.3.0 と同一。

- Windows 10/11 x64
- 一般機能: 任意の x86_64 CPU、3 GB 以上の空き RAM
- voicevox_core (推奨): 数百 MB のディスク + 一般的な CPU
- Irodori-TTS (任意): NVIDIA GPU (CUDA 12.8 対応、VRAM 4 GB 以上)、10 GB 以上のディスク
- advanced 独り言・時事ネタ: OpenAI 互換の LLM（公式 API のほか、LMStudio / Ollama など
  ローカル LLM も可。ローカルなら費用も外部送信も発生しない）

## アップグレード手順

v0.3.x からのアップグレードは、新しいインストーラを上書き実行するだけでよい（currentUser
モード）。`%APPDATA%\ugg\` の既存データは引き継がれる。

**DB マイグレーションが発生する**（v8 → v9、`monologue_cache` の追加）。起動時に自動で
適用され、既存の会話ログ・リマインダー・ToDo・設定はそのまま保持される。ダウングレードは
想定していない。

新機能はすべて既定オフ、または advanced モードでのみ働くので、アップグレードで挙動が
勝手に増えることはない。**v0.3.x で API キーを保存したつもりだった場合は、上記の不具合に
より保存されていない**ので、設定画面で入れ直してほしい（「API キー」の横が「保存済み」に
なれば成功）。

v0.0.3 プロトタイプからの DB マイグレーションは提供しない。
