# ugg v0.5.0 — 宣言どおりに動く

**リリース日**: 2026-09-02
**タグ**: `v0.5.0`
**テーマ**: 契約と実装を一致させる。**新機能はゼロ。**

## なぜこの回だったか

スコープ選定のために契約⇔実装の乖離を洗ったところ、**12 件**見つかった。既知の 3 件
（keyring の store feature 未指定・`persona` の serde 未宣言・口パクの呼び出し元ゼロ）と
同じ型で、いずれも共通の構造を持っていた:

> 契約（spec / 出荷資産 / architecture）は宣言されているのに実装が繋がっておらず、
> **「それらしい名前のテスト」や「成功を返す UI」が発覚を遅らせている。**

3 件なら偶然だが 12 件は構造である。被害の大きい順に 5 件を潰し、同じ見落としが
二度起きないための検査を入れた。

## 直したもの

### 1. `persona` / `prompt` の配線 — advanced の LLM がキャラの人格を知らなかった

`ghosts/*/ghost.json` は `characters.*.persona` / `prompt.style_notes` /
`prompt.max_chars_per_line` を出荷していたが、`GhostManifest` がフィールドを宣言して
おらず **serde が黙って捨てていた**。`advanced.rs` はキャラ説明を「メインキャラ。」
「デスクトップに住む相方キャラ。」とハードコードしていた。

着手前にローカル LLM で A/B を実測した（8 往復 ×2）:

| 指標 | 配線前 | 配線後 |
|---|---|---|
| ミミが「あたし」 | 0/8 | 6/8 |
| クロが「ボク」 | 0/8 | 4/8 |
| 人格の自己申告（懸念した失敗モード） | 0/8 | 0/8 |

数字より重いのは中身で、**配線前は 2 人が別人として成立していなかった** — クロが
「うん、おめでとう。」「私も少しだけおやすみモードにするね」とミミと区別のつかない
同調役になる。配線後は「疲れたなら、ちゃんと休め」「ボクは静かに見ている。」と
毒舌の相方として立つ。**persona 不在は口調の問題ではなく、spec §4.2.4 の掛け合いが
成立していないということだった。**

チャット / 独り言 / 定例会話の言い換えの 3 経路すべてに配線した。

### 2. 月額上限が実質「5 分の一時停止」だった

spec §4.2.7 は「次月リセットで復帰。」と定めているのに、実装は:

- 判定が **LLM 呼び出しの後**（chat 経路）で、超過後も毎回 API を叩いていた
- 降格が `DEGRADE_HOLD_SECS = 300` で自動解除され、**5 分後に advanced へ戻る**。
  しかも上限を超えたままなのに「通常モードに復帰しました」と発話していた
- `cost_limited_emitted` が非永続 `AtomicBool` で立ちっぱなしになり、**月が替わっても
  戻らない**ため翌月の 80% 警告も二度と鳴らなかった
- 定例会話の言い換え経路には判定が無かった
- 既定辞書に `cost_warning_80` / `cost_limit_exceeded` が無く、ゴーストが黙っていた

`cost::check_status` は毎回 DB から当月分を集計するので、**タイマーではなくゲートに
するのが正しい形**だった。3 経路すべてを LLM 呼び出しの前に通し、告知済みは
`app_settings` の当月タグへ永続化した。

あわせて設定画面に当月の利用額を表示し（`manual.md` が以前から案内していたのに
表示先が無かった）、**料金表に無いモデルの警告**を追加した。未掲載モデルはコスト 0 で
記録されるため上限が構造的に発動しない。ただしローカル LLM では 0 が正しいので、
`llm_base_url` がリモートを指している場合のみ警告する。

### 3. 記憶の閲覧・追加・削除 UI

spec §4.2.5 の ★ 要件。`get_profile` / `add_profile` / `delete_profile` は実装済みで
invoke_handler にも登録されていたが、**フロントからの呼び出しが 0 件**だった。
advanced が会話から自動で覚えた内容を見る手段が無く、消すには全部消すしかなかった。

設定 →「AI・拡張」に一覧・1 件削除・手入力での追加を追加し、各項目に
origin（`[自動]` / `[初回]` / `[手入力]`）を表示する。

### 4. 隠している間にリマインダーが無言で消えていた

spec §4.6.1 は「発話不能時のフォールバックとして Windows トースト」と書いていたが、
**実体はアプリ内の 6 秒帯**で OS 通知プラグインは入っていない。`app.emit` はウインドウが
hide されていても `Ok` を返すため到達扱いになり、`advance_after_delivery` が単発
リマインダーを完了扱いにしていた。`reminder_log` には `delivery='toast'` が残るので
**ログ上は「届いた」ことになっていた。**

不可視なら `Deferred` を返すようにした（10 秒ごとの再試行は既存の配線に乗る）。
判定は `governance::can_deliver` に段を足さず `deliver.rs` の到達判定側に置いた
（可視性はガバナンスではなく到達の問題。二重ゲート禁止の維持）。
再表示時に保留分が連打されないよう、起動時の取りこぼし回収が持っていた集約
（「『X』ほか N-1 件」）を共通化して監視ループも通すようにした。

spec §4.6.1 の「Windows トースト」を実態に訂正し、OS 通知の採否は §6.6 の将来課題へ。

### 5. 再発を止める土台

- **契約テスト①**（出荷資産のキー ⇔ serde 構造体）: 出荷 JSON の実キーが「読む」か
  「意図的に無視する（理由つき）」に分類されていることを検査。**これがあれば persona の
  取りこぼしは出荷時点で落ちていた。**
- **契約テスト②**（Rust が引く辞書キー ⊆ 既定辞書）: `cost_warning_80` の欠落を検出する。
- **ログ基盤**: spec §5 が `%APPDATA%\ugg\` の中身として挙げていたのに出力先が無く、
  **リリース版はコンソールが無いため 52 件の `eprintln!` が 1 行も残らなかった**。
  `%APPDATA%\ugg\ugg.log`（2MB で 1 世代退避）に追記する。パニックも残す。

## 実装中に見つけた追加のバグ 2 件

- **`default_shell` が出荷されているのに読まれていない**（契約テスト①が検出）。
  読むと「ゴースト切替でシェルも変わる」挙動になり現仕様と衝突するため、v0.5 では
  理由つきで「意図的に無視」に分類した。採否は spec の判断が要る。
- **ホスト判定がリモートを誤検出**（自分のテストが自分のバグを検出）。
  `https://localhost.example.com` をローカルと誤判定していた。まさに「上限が黙って
  効かない」穴を作る側だった。ホスト部を切り出して完全一致で見る形に修正。

## 検証

- `cargo test` **311 → 329 passed** / warning 0 / `tsc --noEmit` green
- **修正と契約テストはすべて変異テストで有効性を確認した**（配線を外す / 月タグ比較を
  旧挙動に戻す / 資産に未知キーを足す / 辞書からキーを消す、で狙ったテストが FAILED に
  なることを確認し、改変は毎回復元）。「それらしい名前のテストが偽の安心を与えていた」
  のが本リリースのテーマなので、テスト自体を信用しない手順を通している
- 実機確認（隔離 APPDATA の dev、実 DB は不変）: 記憶 UI の一覧・追加・削除 / 当月コスト
  状況の表示 / ログファイルの生成

## v0.5 で扱わなかったもの

- `recall`（契約は 4 箇所に揃っているが `pick_recall` が無く、source_keywords を作る手段も
  無い＝新規設計）
- 問いかけパターン `question_curiosity`（spec と architecture の記述が矛盾。裁定が先）
- 口パク（結線ではなく `AnalyserNode` への置換になる）
- DB の退避・修復（`export_data` が 12 テーブル中 3 つしか出さないため、先に入れると
  リマインダー・ToDo が全損しうる。export 拡張を先に済ませて v0.6）
- **配布まわり**（コード署名・更新導線・SmartScreen）。実ユーザーが開発者本人のみで
  あることを確認済みのため、今は誰も救わない。外部配布を始める時点で改めて載せる
