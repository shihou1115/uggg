## 概要

v0.4.0 (2026-08-17) に対する**外部レビュー指摘への対応**を集めたパッチリリース。新機能は無い。

第三者による読み取り専用のコードレビューを受け、指摘 9 件を実コードで検証した。
事実認定はおおむね正確だったが深刻度には上振れがあり、検証の結果 6 件が妥当、
3 件が「事実は正しいが範囲・前提が不正確」と判定した。本リリースではそのうち
**実際にユーザーが踏みうる 5 件**を修正している。

## 変更点

### DnD アセットの `id` によるパス脱出を修正（最重要）

ドラッグ&ドロップでゴースト/シェルを導入するとき、zip **内部のエントリ名**には
zip slip 対策があったが、**展開先ディレクトリそのものを決める** `ghost.json` /
`shell.json` の `id` が無検証だった。

`id` に `..` や絶対パス（`C:\...`）を入れた配布物を掴まされると、アセット領域の外へ
書き込めた。`Path::join` は引数が絶対パスなら base を丸ごと置き換え、`..` も
正規化せずに OS へ渡すためで、到達点は次の 2 つ:

- **確認なしの `create_dir_all` + 展開** — 新規パスへの書き込みには上書き確認すら
  かからず、ドラッグ&ドロップ 1 回で発火した
- 上書きを承認したときの `remove_dir_all` による再帰削除

`id` を**単一の安全なパス成分**に限定する検証を `parse_manifest`（manifest を読む
唯一の入口）に追加した。空文字・`.`・`..`・パス区切り・ドライブ指定・NUL・制御文字・
前後空白・Windows 予約名・末尾ドットを拒否する。回帰テスト 3 件を追加。

サードパーティ製ゴーストの配布は伺か系では主要な使い方なので、**この経路を使う場合は
v0.4.1 への更新を推奨する**。

### keyring の同期 API が非同期経路をブロックする問題を修正

Windows Credential Manager の同期 API は環境次第で稀にハングする。設定コマンド側は
早くからこれを認識して `spawn_blocking` に逃がしていたが、**LLM 経路 3 本が
`async fn` から同期版を直接呼んでいた**（advanced チャット / 独り言補充 / 定例会話）。

そこで停止すると tokio のワーカースレッドごと止まり、しかも停止するのは LLM 呼び出しの
**前**なので既存のタイムアウトでは救済されなかった。共有の非同期ヘルパ
`get_api_key_async` を追加し、3 経路すべてをそちらへ寄せた。

### SQLite のエラーを「データなし」に変換していた問題を修正

`get_reminder` / `get_todo` / `get_voice_ref` / `get_setting` の 4 箇所が
`query_row(...).ok()` を使っており、「行が無い」だけでなく **DB 破損・型不一致・
I/O エラーまで `None` に変換**していた。

呼び出し側が本来エラーを表示しようとしている箇所（リマインダー・ToDo・参照音声の取得、
初回起動フラグの読み出し）で、DB エラーが「見つかりません」という誤った文言に
すり替わっていた。`rusqlite::OptionalExtension::optional()` へ置換し、
「行が無い」以外は上位へ伝播するようにした。

### カレンダーソース更新がエラーを握り潰していた問題を修正

ソースの追加・削除がメモリを先に書き換え、**DB 保存と キャッシュ消去の失敗を無視して
常に成功を返していた**。保存に失敗するとメモリと DB が食い違い、再起動で設定が黙って
元に戻るのに、ユーザーには成功と表示されていた。

「次状態を組む → DB へコミット → メモリ反映 → イベント通知」の順に統一し、
失敗を呼び出し元へ伝播するようにした。

### 音声の再生完了を待たずに次の吹き出しへ進む問題を修正

TTS の再生完了を待たずタイプライター描画だけを待っていたため、main の音声が
鳴っている最中に sub の文字表示が始まり、長文や低速な合成では**音声の途中で
吹き出しが消えていた**（spec §4.1.3「全ターンの描画+発話完了後に一括消去」に違反）。

描画と再生を同時に開始したうえで**両方の完了を待つ**ようにし、一括消去の直前にも
`whenIdle()` を挟んだ。TTS 無効時・空文字・合成失敗・中断のいずれでも即座に解決される
設計なので、声なし運用のテンポは変わらない。

## 対応を見送った指摘

検証の結果、次は本リリースの対象外とした。

- **月額上限が実質的な上限として機能しない** — 機構の指摘（呼び出し後にチェック /
  降格が 300 秒 / 月をまたいでもフラグが戻らない / 月境界が UTC / 未知モデルは単価 0）は
  事実。ただしレビューが前提とした「仕様では次月まで復帰しないことが期待されている」は
  **spec §4.2.7 に該当する記述が無く**、仕様不整合ではない。上限をどういう約束にするかは
  仕様判断なので次期スコープ検討で扱う
- **DL 資産のハッシュ検証が無い** — 事実だが、全 DL 先が https の公式ドメインで、
  明示同意ゲートの内側にあり、Irodori は GPU 必須のオプトイン。High ではなく Medium と判断
- **Irodori サイドカーが未認証** — 事実だが、合成の使用中のみ起動し 5 分アイドルで
  自動終了、書けるのは WAV のみ。同一ユーザー権限のプロセスならサイドカーを介さず
  直接ファイルを操作できるため、実効的な深刻度は Low
- **LICENSE ファイルが無い / CSP 無効 / CI・フロントエンドテストが無い** — いずれも事実。
  ただし機能不具合ではなく整備項目なので、次期スコープで扱う

なお「test-plan.md が CI を実装済みに近い形で記述している」という指摘は、原文が
当該節を明示的に「雛形」とラベルし、リリース前手順を未チェックのチェックリストで
書いているため**該当しない**と判断した（文言修正はしていない）。

## 契約の変更

無し。**DB スキーマは v9 のまま**、コマンド・イベント・Settings フィールドの追加も無い。

`DndError` に `InvalidId` バリアントを追加したが、これは内部エラー型でフロントへは
既存と同じ文字列として伝わる。

## アップグレード手順

v0.4.0 からは、新しいインストーラを上書き実行するだけでよい（currentUser モード）。
`%APPDATA%\ugg\` の既存データは引き継がれ、**DB マイグレーションは発生しない**。

設定・会話ログ・リマインダー・ToDo はそのまま残る。
